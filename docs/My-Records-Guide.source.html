1  What the module is

My Records is everything an associate files or reviews about themselves. Four screens sit under it, and each has an exact counterpart under My Team that a supervisor uses to review the same data for their direct reports.

2  Attendance

A read-only history of the rows the Dashboard clock creates. One row per day, with time in, time out, break totals and worked hours.

  • Filters. A month selector and a free date range, applied with Filter and reset with Clear.
  • Export. GET /api/user/my-attendance/export streams a CSV of the current filter, behind its own export my attendance permission.
  • Corrections. If a row is wrong, an associate raises an attendance correction. It records the proposed time in, time out and lunch window, and goes to the supervisor's Dashboard queue for approval.
Known rough edge. Choosing a month silently clears a date range you already typed. The two filters are alternatives, but the screen does not say so.

3  Time Entries

The weekly timesheet, modelled on NetSuite: one row per project / task / time type, seven day columns, and a row total. A week moves DRAFT → PENDING → APPROVED, and a sent-back week returns to draft for editing.

This module has its own document. See Time Entries — How It Works for the grid, the lifecycle, the data model and the supervisor view.

Weeks run Monday to Sunday. The API snaps any date you give it to the Monday of its week (Timesheet::weekStartFor), so a timesheet is always addressed by its Monday.

4  Leave Requests

Where leave is filed and tracked. The screen opens with the five credit tiles, then a filter row, then the table.

Column groupHolds
Leave TypeThe type chip — VL, SL, PTO, BDO and so on
Start / End / DurationDates plus All Day, a half day, or a custom time window
Reason / NotesClamped to two lines; hover shows the full text
AttachmentOpens in a preview modal rather than downloading
Submitted / Status / ActionWhen it was filed, where it stands, what you may do

Filing rules

  • Leave may be backdated by at most 30 days; the date inputs enforce the floor.
  • End date may not precede start date.
  • Sick Leave (WITH Medical Certificate) requires an attachment — the form blocks submission without one.
  • Edit is available only while pending.
  • Cancel is available while pending or approved, and asks for a reason that is stored on the row.

Status filter

A single dropdown — All / Pending / Approved / Rejected / Cancelled — with a live count beside each. The All count is the unfiltered total, deliberately not the paginated total of whichever status is selected.

Date filtering is overlap, not containment. Filtering 26–26 October returns a leave running 25–27 October, because the range test is end_date ≥ from AND start_date ≤ to. Containment would have hidden it.

5  Leave credits and the observer

Credits live in one leave_credits row per user per year, and are moved automatically by LeaveObserver as a leave changes state — never by hand from this screen.

EventEffect
Leave createdDays are added to the matching *_pending bucket
ApprovedDays move from *_pending to *_used
Rejected or cancelledDays come out of *_pending
DeletedPending days are released
Do not move leave rows behind the observer's back. Force-deleting leaves in the database does not reverse the credit arithmetic, which leaves used and pending overstated. Rebuild with migrate:fresh --seed instead.

6  My Shift

Shows the shift currently assigned and the history of changes. An associate may request a different shift: they pick from the available shifts, give an effective date and a reason, and the request lands in their supervisor's Dashboard queue.

PENDING→ APPROVED→ APPLIED PENDING→ REJECTED

applied marks a request whose effective date has arrived and whose shift is now live on the user record.

7  Shared screen conventions

Every screen in the module is built the same way, so behaviour transfers:

  • A title bar card holds the heading and the primary action.
  • Filters and results share one bordered card; filter fields use a notched outline with the label sitting on the border.
  • Filters apply on Filter, not as you type, and Clear resets them.
  • Tables scroll horizontally below their minimum width; below lg they become stacked cards rather than shrinking.
  • Long text is clamped to two lines with the full value on hover.
  • Pagination sits inside the table card.

9  Permissions

All six roles hold the full My Records set — attendance, time entries, leaves and shift. The module is personal data, so the scope is always the signed-in user; there is no permission that widens it to someone else's records. Seeing another person's data is what My Team and the HR modules are for.
