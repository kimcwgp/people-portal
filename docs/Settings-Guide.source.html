1  What the module is

Settings holds the four reference lists the rest of the application selects from. Nothing here is transactional — these are the options that appear in other modules' dropdowns, and changing one changes what everybody can choose.

ProjectsTime entry linesprojects
ClientsProjectsclients
Leave TypesLeave requests, proxy leavesleaves_type
ShiftsUser accounts, shift change requests, attendanceshifts

2  Projects

The work people book time against. A project row carries a name, its client, a project type and a description.

FieldNotes
Project NameRequired
ClientRequired; drawn from the Clients list
Project TypeRequired; e.g. Web Application, Mobile Application, Data & Analytics
DescriptionOptional; clamped to two lines in the table, full text on hover

Filters cover a name search, client, project type and page size.

No project manager field. The company does not have a project manager role, so pm_id and its relation were removed from the model, API, validation and seeder. The Glip webhook column went with it.

3  Clients

The companies projects belong to: name, parent company, contact name, contact number and description. Each row shows a live count of the projects attached to it.

4  Leave Types

The kinds of leave that can be filed. Each has a display name and a short code; the code is what ties a type to a credit bucket.

CodeDraws from
VLVacation leave credits
SLSick leave credits
ELEmergency leave
BLBirthday leave — one per year, subject to tenure
ML / PLMaternity / paternity
LWOPLeave without pay — draws no credit
One name is load-bearing. Leave Requests decides an attachment is mandatory by testing whether the type name contains WITH Medical Certificate. Renaming that type past the phrase silently turns off the requirement.

5  Shifts

The working windows an associate can be assigned to. A shift is a type (day or night) plus a start and end time; duration is derived, and a window crossing midnight is handled by adding 24 hours rather than reporting a negative span.

The screen opens with three summary tiles — Total, Day and Night — which count the whole roster and are deliberately unaffected by the filters below. Each row shows how many users are on that shift.

6  What depends on these lists

Clients→ Projects→ Time Entries
Leave Types→ Leave Requests→ Leave Credits
Shifts→ User accounts→ Attendance & shift changes

7  Deletion rules

Each list guards deletion differently, according to what would break:

ListRule
ClientsBlocked while projects are attached; the dialog names the count and asks you to reassign first
ShiftsDelete is disabled while users are assigned; the button explains why on hover
ProjectsSoft-deleted, so historical time entries keep their reference
Leave TypesRestricted at the database level — a type in use cannot be removed
